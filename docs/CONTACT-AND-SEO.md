# Contact forms and site optimization

The contact page includes a starter form with name, email, inquiry type, and message. In Content studio, **Contact forms** lets the artist change the wording, placement, prefilled answers, required fields, choices, order, and field widths; create more forms; and archive questions. Supported inputs are short/long text, email, phone, URL, number, date, dropdown, radio, checkbox, and multiple checkboxes. The public controls use the saved site theme. Changes follow Save draft → Preview → Publish. Preview submissions never save or send.

**Contact inbox** reads private responses from a separate Netlify Blobs store, with newest-first pagination and reversible archiving. Each response retains the original question labels. Submissions validate against the published form, enforce a shared per-source limit and honeypot, and use a durable request ID to avoid duplicate responses or uncertain email retries. Private recipients and notification switches are omitted from the public form payload. All inbox reads and changes require the existing administrator session.

Email notifications start off. Their destination is editable per form. To send, enable both the form's notification switch and **Outgoing email**, configure the existing verified sender and Gmail OAuth or SMTP environment settings described in `.env.example`, then publish. Secrets remain in server configuration. Responses save even with email off, unavailable, or unconfirmed. The inbox distinguishes those states from provider acceptance; acceptance does not assert delivery to a mailbox.

Public pages now have canonical `https://waamb.at` URLs, descriptions, Open Graph and Twitter cards, and verified 1200×630 sharing images. Content-hashed JPEGs under `/social/cards/` are served directly, avoiding runtime font-rendering inconsistencies. `src/content/social-images.json` maps the default page cards; new pages use the artist card until a custom image is supplied. Regenerate the defaults with `node --import tsx scripts/generate-social-cards.tsx`, then run tests and visually check the images before committing. The generator and tests check that the brand labels actually render. Each page's Search and social sharing controls can override its title, description, or sharing image, or hide it from search. `/robots.txt` excludes admin/API routes; `/sitemap.xml` includes active indexable pages. Preview/private builds are excluded from indexing. Admin protection still depends on authentication, not robots.txt.

Painting posters have responsive AVIF/WebP renditions and an eager, high-priority first image rendered in the initial HTML. Posters stay visible until a video actually plays. Phone source selection happens before attaching a video, preventing an initial desktop download. The failing legacy Adobe JavaScript loader was removed; the original Adobe-hosted font-face is inlined to avoid a blocking stylesheet request. Semantic heading order was corrected while retaining the existing visual sizes and spacing. Artwork and outbound source links open a new tab; playback controls retain their existing behavior.

`node scripts/optimize-site-media.mjs [cache-directory]` regenerates content-addressed media, using Sharp from Next.js and a local ffmpeg binary (`FFMPEG_BIN` can select it). Painting display copies retain the complete loop at 960px and 640px. Original source and token URLs remain in content; already-customized display URLs are preserved. Autocorrection's expired Imgur URL is recovered from the exact IPFS artifact in HEN token 725958. The manifest records source hashes and byte sizes. Hero files are copied byte-for-byte to hashed URLs. Content-addressed painting and sharing-card files receive immutable caching; mutable `/hero/` URLs retain their previous policy.

The admin entry remains the existing `https://waambat.netlify.app/admin` authentication host. This change does not expand the approved test-account hosts or replace existing identity-provider callbacks.

## Progressive delivery and form controls

`prepare-adaptive-media.mjs` builds full-duration H.264/fMP4 HLS variants with aligned two-second segments. It verifies every frame against the source display file, starts at 384px (360px for the portrait hero), and provides 640px phone / 960px gallery variants. Phone playlists exclude the desktop gallery rendition. `useAdaptiveVideo` loads the light HLS player only for requested videos, bounds forward buffering, keeps a still until a painting is at least half visible (or explicitly played), stops loading on pause/offscreen/menu visibility, and falls back through native HLS to the existing MP4. Artist-edited sources remain untouched. The montage and its ending loop keep their separate phases.

Posters have 384/640/768/960px AVIF and WebP versions. The representative hero still appears before video starts. Content hashes cover the playlist and segment bytes; `/streams/` and `/paintings/` use immutable caching. Originals and token links are retained.

To regenerate, run `FFMPEG_BIN=/path/to/ffmpeg node scripts/prepare-adaptive-media.mjs /path/to/cache`. Once those videos exist, `ADAPTIVE_REUSE_POSTERS=1` reuses the generated poster mappings during validation. Then run `FFMPEG_BIN=/path/to/ffmpeg node scripts/prepare-contact-media.mjs /path/to/JC0hAbH.mp4` to add the exact contact animation and its initial still; this prevents upstream Imgur 403s from breaking contact-page playback. `evidence/adaptive-media.json` and `evidence/contact-media.json` record actual frame counts and rendition sizes.

The public form uses reusable themed controls with floating labels, a keyboard-operated custom listbox, native validation/FormData integration, press/sending feedback, and reduced-motion support. Long custom questions use a full wrapping label. The submit control stays 44px tall with an animated fill on hover/focus; confirmation text has no decorative border.

The mobile menu retains the original header or hero wordmark at its existing coordinates. An in-page overlay permits ordinary stacking while the enclosing site provides modal semantics, background inertness, focus containment, Escape dismissal, and scroll restoration. Choosing a navigation link closes the menu as the Next navigation begins; modified clicks leave the current menu intact.
